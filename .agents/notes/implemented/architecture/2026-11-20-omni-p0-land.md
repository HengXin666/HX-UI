# Agent Note: omni 1.0 的未提交改动由一个本机脚本备份后按依赖顺序分 7 批提交

Status: implemented

Decision-ID: omni-p0-land

## Code

- `scripts/p0-land.ts`
- `scripts/constants/p0-land.ts`

## Problem

omni 1.0 从 2026-11-18 起的批 1~11, P1 两批, P2 第一批共 97 个文件 (81 个新文件, 16 个改动文件) 全部只在工作区, HEAD 停在 `51136bd`. 一次误 checkout 或 stash 就会全丢. `package-lock.json` 截断在 60000 字节, `npm ci` 会挂; 测试依赖 (vitest, happy-dom, @testing-library/*, axe-core) 不在 devDependencies. Hark 经 hxoa 只能读写文件, 不能执行 git 与 npm, 所以提交必须由用户本机一条命令完成.

## Decision

- `scripts/p0-land.ts`: 先把改动备份到 git 忽略的 `.hark/` (diff patch, 改动文件 tar 包, `git status` 存档); 再 `npm install` 重写 lock, 测试依赖按 `node_modules` 里已装的版本钉进 devDependencies, 本机没装的只报出不取 latest; 然后按清单逐批 `git add` 精确路径, 跑 `npm run gates:staged`, 通过才 commit, 失败即停并给出 `--from <批>` 续跑命令; 最后 `git switch -c refactor/omni-1.0` 并建 `src/data` `src/model` `src/sections` `src/templates` 四个空目录, 打印清单外剩余改动. `--dry-run` 只打印.
- `scripts/constants/p0-land.ts`: 批次清单与全部字面量. 清单由逐文件比对 HEAD `51136bd` 的 git blob 哈希得出, 每个文件只进一批. 批次按依赖排序 (land → motion → page → data → commerce → marketing → docs), 共享的聚合文件 (`src/page/index.ts`, `src/page/registry.ts`, `src/blocks/marketing/index.ts`, `package.json`) 放进它最后依赖的那一批, 保证每批的相对导入只指向更早的批或 HEAD 里已有的文件.
- 不 push, 不 reset, 不 stash, 不 checkout 已有分支, 不删文件; 路径由 `git rev-parse --show-toplevel` 运行时解析.

## Alternatives considered

- 什么都不做, 让用户手工 `git add` 提交: 最强理由是零新代码, 用户完全掌控. 否决: 97 个文件跨 6 个主题, 手工分批容易漏文件或把共享聚合文件放进过早的批导致门禁挂; 也没有备份步骤.
- 复用现有, 一次 `git add -A` 一个大提交: 最强理由是最快, 不会出现中间态门禁失败. 否决: 历史无法按主题回看与回滚, 也会把清单外的杂物一起带进去.
- 按原计划的 16 批 (批 1~11 各一批) 提交: 最强理由是与实施记录一一对应. 否决: `src/page/index.ts`, `src/motion/index.ts`, `src/tokens.css` 等文件同时承载多个原批的改动, 整文件粒度无法拆开, 早批的快照会引用尚未提交的导出.

## Consequences

提交历史是 7 个主题提交, 不再与批 1~11 一一对应; 实施记录仍在 `.hark/plan.md` 附录. `docs/architecture/omni-1.0.md` 改名 `omni-1-0.md` 不在本脚本内, 留给 P1 收尾批. 杂物 (`hx-ui-0.1.2.tgz`, `.tmp-check/`, `.playwright-gif/`) 已被 `.gitignore` 覆盖, 不需处理.
