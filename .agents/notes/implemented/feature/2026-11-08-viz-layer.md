# Agent Note: 可视化层用纯 SVG 与运动令牌做数据, 流程和内容的图

Status: implemented

Decision-ID: viz-layer

## Code

- `src/viz/use-stage.ts`
- `src/viz/charts/BarChart.tsx`
- `src/viz/flow/flow-layout.ts`

## Problem

库里画数据只有两条路: `src/charts` 包装 recharts, 以及 studio 里的 `Spark`, `Metric`, `Process`, `Compare`. 前者的入场和更新由 recharts 自己决定, 与 `docs/research/craft.md` 的弹簧, 发牌和减弱动效合同对不上. 后者只有四件, 没有柱状, 漏斗, 时间线, 流程图和环形进度, 也没有共享的比例尺数学. 拼电商活动页, 软件产品页和运营看板时, 数据区块是最缺的一层.

## Decision

新增 `src/viz`, 从子路径 `@hx/ui/viz` 进入, 不进根桶.

- `scale.ts` 收齐纯数学: linear 比例尺, nice 刻度, `punchDomain` (新值越界时 domain 只外扩), 路径, 发牌错峰. 单测直接覆盖.
- `use-stage.ts` 是所有图共用的舞台: 视口触发一次, 减弱动效时过渡为 0, 首次入场按发牌错峰, 之后的数据更新走 thumb 弹簧从当前值继续. 组件里不写秒数.
- `charts/`: `BarChart` (scaleY, 坐标轴重标, roving tabindex), `Trend` (坐标轴冲击, 越界那一次放 1px 扩散圈), `Ring` (1px 环加端点, progressbar 语义).
- `flow/`: `layoutFlow` 按依赖深度分列的自动布局, `FlowGraph` (级联生成, 当前节点的进出边主色, 脉冲走两趟后停), `Funnel` (scaleX 条加级间转化率), `Timeline` (滚动绑定且可逆的进度线).
- 每种图的手感对齐 video-shotcraft 镜头卡 (`docs/research/video-shotcraft.md`): 坐标轴冲击先坏一拍再重标 (`use-shock.ts`), 环形入场满弧自检, 流程图连线先于节点, 漏斗落定后报数, 时间线弹卡立起. 帧数换算集中在 `tokens.ts`, 对照表在 `docs/architecture/layers.md` 第 3 节.
- 只动 transform, opacity, pathLength 与 strokeDashoffset. 线宽 1px, 颜色只走语义令牌, 读屏只读终值.
- 入口同时转出 studio 的四件与 `NumberRoll`, 使用方从一处取齐.

## Alternatives considered

- 什么都不做 / 复用现有 `src/charts` 的 recharts 包装: 最强理由是 recharts 已经是依赖, 坐标轴, 提示框和响应式都现成. 否决: 它的动画不可中断, 不读运动令牌, 也没有流程图和漏斗, 改造它的内部比写一层 SVG 更重.
- 把新图塞进 `src/studio/viz`: 最强理由是那里已经有 Metric 和 Process, 改动最少. 否决: studio 是镜头语言加两张样板页的子路径, 数据层和它的生命周期不同, 混在一起后废弃 studio 时会连带数据层.
- 引入 d3 或 visx: 最强理由是比例尺和布局算法成熟. 否决: 这里只用到 linear, nice 和一个分层布局, 不到两百行, 新增直接依赖要过 HC-DEPS 批准, 不划算.

## Consequences

数据区块不再依赖 recharts, 可以直接放进 `@hx/ui/page` 的页面描述. 复杂图表 (多轴, 堆叠, 地图) 仍走 `src/charts`. `FlowGraph` 的布局只按依赖深度分列, 不做交叉最小化, 节点多于二三十个时连线会交叉, 那时应换专门的图编辑器 (`src/blueprint`).
