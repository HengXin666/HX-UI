# 站点区块 (V1-01): 顶栏 / 大菜单面板 / 移动导航 / 公告条 / 页脚

Decision-ID: blocks-site-v101

## Code

- src/blocks/site/SiteHeader.tsx
- src/blocks/site/parts/header-parts.tsx
- - src/constants/blocks-site-v101.ts
- docs/src/pages/blocks/site-v101/SiteBlocksPage.tsx

## Problem

design 4.1 要求 site 类区块数据驱动, 可被 PageComposer 拼整页, 同时承接 BlockBaseProps; src/site 已有零件 (SiteHeader, MegaMenu, MobileNav, AnnouncementBar, SiteFooter, SearchOverlay, LocaleSwitcher, ThemeSwitcher) 只吃 ReactNode 与 SiteLink 形状.

## Decision

遵循 docs/architecture/component-contract.md. 区块只做 "数据 -> 零件" 适配 (adapt.ts) 与 BlockShell 外壳, 不重写零件:
- 五个区块: SiteHeader, MegaMenuPanel (design 中是独立区块), MobileNav, AnnouncementBar, SiteFooter (design 2 命名, 无 Block 后缀; 与 src/site 同名零件以 import 别名区分); siteBlockRegistry 以 design 名词名注册.
- 内容类型只从 src/blocks/_shared/types.ts 导入; 区块自有 props 在 src/blocks/site/types.ts.
- 顶栏外壳承担 sticky / fixed / absolute 定位, 零件退回 relative, 避免 sticky 被外壳高度困住; 透明覆盖时公告进外壳.
- width 映射零件容器档 (外壳贴边), tone 映射顶栏底色 / 页脚由外壳上色, align=center 导航居中.
- aria 名称: ariaLabels prop > BlocksProvider 内置包兜底键 (SITE_BLOCK_ARIA_FALLBACK), 因 BlockLabels 无站点专属键且不得改公共类型.
- 公告条 tone 与 BlockBaseProps.tone 冲突, 语义色另设 intent, 缺省由 tone 推出.

## Alternatives considered

- 什么都不做 / 直接用 src/site 零件: 零件不吃 JSON, 不能进 PageComposer, 也没有 BlockBaseProps; 否决.
- 区块内重写顶栏与菜单: 重复零件的 radix 键盘与焦点逻辑, 违背 "复用零件"; 否决.
- 在 _shared/types.ts 增加站点 aria 键: 公共类型归基座任务, 本任务不改; 否决.

## Consequences

- 顶栏下拉每个入口只显示第一张特色卡 (零件限制); 多卡完整展示用 MegaMenuPanelBlock.
- 平铺导出名 (SiteHeader 与 L1 零件同名) 由 V1-Z 在 src/index.ts 决定. props 类型保留 XxxBlockProps 名以免与零件类型撞名.
