# Agent Note: 门禁总线 scripts/gates 从 .mjs 迁到 .ts, 并修 porcelain 行首被 trim 的分流 bug

Status: implemented

Decision-ID: gates-ts

## Code

- `scripts/gates/git-changes.ts`
- `scripts/gates/shared/probe-gates.ts`
- `scripts/gates/shared/probes/kit.ts`
- `scripts/gates/frontend/check-line-budget.ts`
- `scripts/constants/gates.ts`

## Problem

AGENTS.md 要求脚本只写 .ts, 而门禁总线的 8 个文件 (`run`, `registry`, `lanes`, `shared/check-lanes`, `shared/probe-gates`, `shared/check-fingerprint`, `frontend/check-line-budget`, `frontend/check-docs-registry`) 仍是 .mjs, 只靠 baseline.json 里的 HC-EXT 历史条目放行. 它们在 .mjs 下也逃过了只扫 .ts/.tsx 的规则 (常量重复, 文件头注释长度, 注释标点, 文件行数), 改成 .ts 后这些历史问题会整体算作新增.

另有一个真 bug: `run` 的 `git()` 对每行输出做 `.trim()`, 再在 `changedFiles()` 里用 `replace(/^..\s/, "")` 去掉 porcelain 状态码. 状态码以空格开头时 (`" M docs/x"` 表示只改了工作区) trim 先吃掉行首空格, 状态列整体左移, 剥前缀的正则不再落在正确的列上, 得到的不是路径 (`"M docs/x"`, 或按旧注释说的 slice(3) 写法得到 `"ocs/x"`). 这些串不匹配任何 lane 前缀, 于是无参数运行总线时被报成"未认领路径"并全量兜底; 上一次提交时报出的 6 个未认领路径就是这个原因, lane 分流在工作区模式下实际上失效.

## Decision

- 8 个文件改名为 .ts, 保持 JS 语义, 只加 Node 类型剥离支持的注解 (type 别名, 参数与返回类型, `import type`), 不用 enum / namespace / 参数属性; 相互 import 写 .ts 扩展名. 改名之外的拆分: `probe-gates` 拆成运行器加 `shared/probes/` 下的夹具工具与两组探针 (原文件 558 行, 超过 HC-SIZE 300 行与行数棘轮 450 行); `check-fingerprint` 把第一组 ("多严") 的抽取器移到 `shared/fingerprint-sources.ts`, 第二组 ("还跑不跑") 的 `wiringOf` 留在原文件.
- 分组名, 解释器, 门禁文件路径, 退出码等在多个门禁文件里重复 3 次以上的字面量集中到 `scripts/constants/gates.ts` (门禁总线专用的第三份常量池, 不 import 质量门禁或浏览器检查的常量).
- porcelain 解析独立成 `git-changes.ts` 的 `parsePorcelain`: 只去行尾空白, 从固定第 4 列取路径, 改名行取 `->` 之后的新路径; `--name-only` 输出仍按行两端 trim. 负向探针新增一条控制组 (`总线 控制组: porcelain 行首空格状态码`), 直接对 `parsePorcelain` 断言 `" M docs/x.md"` 等五种行解析出完整路径, 回退到旧写法即 FAIL.
- 指纹的 `registry:gates` 与 `registry:lanes` 从"正则抽注册表源码文本"改为"按扫描根 import 模块后序列化求值结果" (仍不取 label). 原因: 分组名与 argv 改为引用常量后, 正则只能读到标识符, 常量值被改也不会动指纹; 求值后常量值变化同样会动指纹, 不比原来宽松. `thresholds:check-docs-registry` 追加 `scripts/constants/gates.ts` 的 token 指纹, 因为该门禁的扫描路径片段 (`SRC_DIR` / `DOCS_DIR`) 现在来自那里.
- `run` 的 preflight 原来只认以 .mjs / .json 结尾的参数, 迁到 .ts 后会让整批门禁 (以及原本就是 .ts 的 icons / smoke / shell) 跳过存在性检查; 改为认 .ts / .mjs / .json.
- 探针夹具两处顺手修正 (迁移后首次跑 probe 时发现, 与改名无关): `docsSkeleton` 补上 2026-11-03 起登记进 lane 表的 `tests/`, `vitest.config.ts`, `CHANGELOG.md`, 否则 "lanes 控制组" 因 dead-lane-prefix 必然 FAIL; 门禁子进程带 `GIT_CEILING_DIRECTORIES=<夹具根>`, 否则系统临时目录落在另一个 git 仓库里时, 门禁的 `git ls-files` 会在外层仓库里成功返回空清单而不是退回目录遍历, 分流与行数的 5 条探针全部读到空仓库.
- 文件头注释压到 10 行以内 (HC-COMMENT), 设计理由保留在各声明上方的注释与本 note 中; 注释里的全角标点改为 ASCII (HC-TEXT), 字符串内容不变 (探针按输出文本断言).
- 引用同步: package.json 与 docs/package.json 的 scripts, 仓库内钩子 pre-commit / pre-push / install.sh, CI workflow quality.yml, README.md, docs/code-quality-landscape.md 的门禁路径, 以及 v2 接入, PR 3 CI 修复, lanes 顶层条目, 文档站页面这几篇 note 里指向这些 .mjs 的路径 (常量池 note 补一句第三份 gates.ts; tsconfig.build 入 lib lane 那篇正文里的旧路径未改, 该 note 缺 Status 行, 一改就会被红线判 note-format 错误). docs/reference/ 下的历史文档不改. baseline.json 删除这 8 个 .mjs 的 HC-EXT 条目, 未新增条目.
- 指纹 `--update`: 本次是有意的接线变化 (npm scripts, 钩子源文件与 workflow 的命令路径从 .mjs 换成 .ts), 加上注册表 / lane 表 / check-docs-registry 抽取口径的上述变化. 同一次 update 还吸收了一条早于本次的漂移: `thresholds:check-ui-rules` 在 #43 (01cb8fa) 改 `scripts/constants/quality.ts` 的 `DOCS_APP_PATHS` (加 docs/face/) 与 `DOC_TOP_DIRS` (加 research) 后没有刷新快照; 那是文档站目录归属的扩展, 已在该提交说明理由, 本次只是显式承认. 没有任何阈值被放松.

## Alternatives considered

- 什么都不做 / 复用现有: 最强理由是 .mjs 能跑, baseline 已经放行, 改名会把一批历史问题翻成新增. 否决: AGENTS.md 明确只许 .ts, baseline 只该缩小; 且 porcelain bug 让工作区模式的分流全量兜底, 不修就一直多跑, 并持续产生误导性的"未认领路径"提示.
- 只修 porcelain bug, 不迁移: 改动最小. 否决: bug 修复会让 run.mjs 进入 diff, 迁移迟早要做, 分两次会让同一批文件的指纹和 note 各折腾一遍.
- 常量放回 `scripts/constants/quality.ts`: 少一个文件. 否决: quality.ts 属于质量门禁且被 `thresholds:check-ui-rules` 整份哈希, 门禁总线的常量放进去会让两边互相触发指纹变化.
- 指纹继续用正则读注册表文本: 不需要 import 被检查的模块. 否决: 常量化后正则读不到值, 那是静默放松.
- 把 porcelain 的验证写成 node:test 单测: 更标准. 否决: 需要同时改 scripts/quality/ci.json 与影响图; 放进本来就要跑的负向探针, 与"证明门禁真的会红"的职责一致.

## Consequences

`node scripts/gates/run.ts` 取代 `run.mjs`, 所有入口 (npm scripts, 钩子, CI) 指向 .ts; 本地已安装的钩子是指向仓库内源文件的符号链接, 不需要重装. 工作区模式下 `" M"` 类路径能被 lane 正确认领. 门禁总线文件受 .ts 规则约束, 新增门禁时字面量与注释同样要守规. 探针总数从 19 条变为 20 条 (README 原写 17 条, 已改为 20). 指纹抽取改为 import 注册表与 lane 表, 这两个模块必须保持无副作用.
